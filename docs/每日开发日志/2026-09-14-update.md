# 2026-09-14 开发日志

## Markdown 功能立项（方案先行）

- **需求**：工作/生活/阅读/目标等所有涉及文字编辑的地方支持 Markdown 语法，让记录结构更清晰。
- **分支决策**：从 `main`（`daea678`）切出 `feature/markdown`，独立分支便于整体 review 与回退。
- **方案决策（用户拍板）**：选择**方案 B — 自研轻量渲染器**，坚持零三方依赖原则。
  - 支持子集：标题 `#~######`、粗体/斜体、无序/有序列表（一层嵌套）、引用、行内代码、代码块、分隔线、链接（V1 显示为文字+下划线，不跳转）
  - non-goals：表格、图片、脚注、链接跳转
  - 数据层**零迁移**：数据库存原始 Markdown 字符串，存量纯文本天然是合法 Markdown，完全向后兼容
  - 接入原则：**只接长文本内容字段**，标题/名称类字段不接
- **方案文档**：`docs/资料与方案/Markdown功能方案.md`

## 过程中修复的 4 个问题

1. **浅色模式下笔记正文白字不可见**
   - 根因：`markdown_text.dart` 的 `_base()` 用外部传入的 `baseStyle`（详情页只给字号/行高，**没带 color**）直接替换了主题 `bodyMedium`，丢掉明暗自适应颜色。`RichText` 与 `Text` 不同——**不继承 DefaultTextStyle**，无 color 的 TextSpan 按渲染默认色（白）显示。
   - 修复：改为 `bodyMedium.merge(baseStyle)`，主题色为底、外部只覆盖字号行高。

2. **保存后摘要显示字面量 `$1`（工作模块与阅读模块同现）**
   - 根因：`stripMarkdown()` 用 `replaceAll(RegExp(...), r'$1')` 做捕获组回填——**Dart 的 `replaceAll` 不解析 `$1` 分组**（那是 JS 语法），直接把 `$1` 当字面量写入结果。
   - 证据：`dart run` 实测对比，`replaceAll` → `$1`，`replaceAllMapped` → `重点`。
   - 修复：4 处捕获组替换（行内代码/链接/粗体/斜体）改 `replaceAllMapped`。
   - **数据安全**：`$1` 只出现在展示层，库中存的仍是原始 `**重点**`，无需数据修复。
   - 顺带修：分隔线正则漏 `multiLine: true`（静默失效，不报错只漏替换）；有序列表摘要被抹掉序号（改为保留 `1. `）。

3. **工具栏标签调整**（用户反馈）
   - `❝` → `>`（引用功能不变，标签改为真实语法符）
   - `<>` → `---`（新增 `_insertDivider()`，保证 `---` 独占一行，光标落到下一行）

4. **构建 OOM（非代码问题）**
   - 现象：`flutter run` 连续两次失败——先 Gradle JVM `Native memory allocation (malloc) failed: Chunk::new`，后 Dart 编译器 `allocation.cc: Out of memory`。
   - 根因：本机 16GB 物理内存、页面文件自动管理 12.8GB，**提交内存上限仅 28.3GB，常态占用 26GB+**（可用常剩 0.2~1.7GB）。`android/gradle.properties` 原配置 `-Xmx8G -XX:MaxMetaspaceSize=4G` 对 16GB 机器严重超标。连 `gradlew --stop` 都因 JVM 起不来而失败。
   - 处理：① gradle.properties 降配为 `-Xmx2048m -XX:MaxMetaspaceSize=1024m -XX:ReservedCodeCacheSize=256m`，去掉 `HeapDumpOnOutOfMemoryError`；② 强杀残留 Gradle daemon；③ 清理 `android/hs_err_pid*.log`、`replay_pid*.log`（已被 `.gitignore` 的 `*.log` 覆盖）。
   - commit：`082e3b1`（`chore: 降低 Gradle JVM 内存配置，修复 16GB 机器构建 OOM`）
   - 待办（可选）：页面文件固定为 24GB 提升提交上限，需管理员 + 重启。
