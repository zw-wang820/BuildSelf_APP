# 工作模块 - 交互说明

> 版本：v0.1（待审核）
> 范围：工作记录类型体系重构 — 支持「心得 / 思考 / 工作日志 / 待学习项」等结构化记录
> 前置：工作模块已有基础（WorkNote 记录 + 列表/详情/编辑 + 用户自定义分类）

---

## 一、现状分析

| 现状 | 说明 |
|---|---|
| 记录类型 | 仅 3 类：经验 / 心得 / 反思（`WorkRecordType` 枚举，但存储为自由字符串，兼容旧数据） |
| 已有能力 | 标题+内容+标签+心情+图片附件、列表筛选（全部+自定义分类）、详情、编辑、回收站 |
| 与需求的差距 | ①「工作日志」无类型；②「待学习项」无类型且**缺完成状态**；③「思考」与现有「反思」语义重叠 |

---

## 二、类型体系建议（核心设计）

### 推荐：4 类统一类型 + 自定义分类打标签

| 类型 | emoji | 定义 | 对应现状 |
|---|---|---|---|
| **💡 心得** | 💡 | 工作收获、经验总结（"学到了什么"） | 合并现有「经验 + 心得」 |
| **🤔 思考** | 🤔 | 工作思考、问题分析、灵感（"想到了什么"） | 合并现有「反思」→ 思考 |
| **📝 工作日志** | 📝 | 每日工作流水记录（做了什么/进展/计划） | 新增 |
| **📚 待学习项** | 📚 | 想学/要学的技能知识（**清单式，带完成状态**） | 新增 |

> 现有「用户自定义分类」（健身、重要…）继续保留，作为记录上叠加的标签维度（如"心得 + 项目A"），与类型正交。

### 为什么这样合并
- 现有 3 类（经验/心得/反思）语义与需求重叠，直接堆 5-6 类会让"选类型"变重；合并成 4 类心智清晰
- 旧数据兼容：`recordType` 是字符串，映射表把 `experience`→心得、`reflection`→思考，**存量记录自动归类，零迁移成本**

---

## 三、待学习项的特殊设计（清单 + 完成状态）

待学习项不是普通笔记，本质是**可勾选的清单**：

- **字段**：`WorkNote` 新增 `done`（0/1）+ `done_at`（完成时间）——v9 迁移
- **列表交互**：待学习项在列表中以清单形态展示：✓ 勾选框 + 学习内容；点勾选完成（划线 + 完成时间），再点取消
- **编辑页**：待学习项类型下，表单变为"学习内容 + 完成状态"双要素
- **统计**（可选后续）：已完成/未完成计数、按时间线看学习进展

---

## 四、工作日志的结构化引导

日志若只是自由文本，容易记成流水账。建议在**编辑页按类型给出模板提示**（不放数据库，纯 UI 引导）：

```
📝 工作日志 编辑引导：
  · 今天完成了什么？
  · 遇到什么问题 / 怎么解决的？
  · 明天计划做什么？
```

- 三个引导作为输入框 hint 或占位分段，用户可自由填写或留空
- 列表卡片对日志类显示"日期 + 摘要"（截取前两行），适合快速回顾

## 五、交互流程

### 列表页（工作 tab）

```
┌────────────────────────────────────┐
│ 工作记录                     ＋ 新建 │
│ [全部] [💡心得] [🤔思考] [📝日志] [📚待学]│ ← 类型 chips（+ 自定义分类收起）
│ ┌────────────────────────────────┐ │
│ │ 💡 心得 ｜ 标题/内容摘要 ｜ 标签   │ │
│ │ 🤔 思考 ｜ ……                  │ │
│ │ 📚 ☑ 学习 Flutter 状态管理      │ │ ← 待学项：勾选框 + 划线态
│ │ 📝 8/31 日志 ｜ 今日完成…        │ │
│ └────────────────────────────────┘ │
└────────────────────────────────────┘
```

| 环节 | 行为 |
|---|---|
| 类型筛选 | 顶部 4 类型 chips +「全部」；自定义分类收纳到「分类」入口（原位置不动） |
| 待学习项 | 列表内直接勾选完成/取消（不进入编辑页），完成项划线 + 绿色对勾 |
| 新建 | FAB → 编辑页，默认上次使用的类型 |
| 搜索 | 沿用现有搜索（按标题/内容/标签） |

### 编辑页

- 顶部**类型选择**（4 个 emoji 分段，切换时表单引导随之变化）
- 日志类型：三段引导占位（完成/问题/计划）
- 待学习项：内容输入 +「已完成」开关
- 其余（标题/标签/心情/附件）沿用现有

### 详情页
- 类型徽章（emoji + 名称）+ 完成状态（待学项显示 已完成/未完成 + 时间）
- 其余沿用现有

## 六、数据与实现要点

1. **迁移 v9**：`work_notes` 表加 `done INTEGER NOT NULL DEFAULT 0`、`done_at TEXT`。
2. **类型映射**：扩展 `_normalizeRecordType`（experience→心得、reflection→思考）；`WorkRecordType` 枚举改为 4 类（心得/思考/工作日志/待学习项）或保留字符串+常量表。
3. **改动文件**：`work_models`（done/doneAt + 常量）、`work_repository`（toggleDone 方法）、`work_list_screen`（类型 chips + 待学项勾选）、`work_edit_screen`（类型选择 + 引导 + 完成开关）、`work_detail_screen`（徽章/状态）、`enums.dart`（类型枚举）。
4. **不破坏现有**：自定义分类、标签、回收站全部保留；旧记录按映射自动归类。
